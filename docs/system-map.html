BDMF System Map

Two drawings of the same platform. The first shows what exists and which walls separate it; the second shows what the system decides, and what it refuses.

01What exists

BDMF is one installation serving many client companies. The structure below is not really a hierarchy of pages — it is a hierarchy of walls. Three zones, each of which can see strictly less than the one outside it.

  • Tenant boundary
  • Reachable without an account

02Who gets in

Every request resolves through the same four questions before a single row of client data is read. Note where the tree does not branch: there is no path from a contributor's link to a project, and no path from one workspace to another.

Why a token and not a password. A chief executive asked to score thirteen initiatives should not have to create an account to do it. The invitation link is a single-purpose credential, stored only as a hash, scoped to one page, and expiring. Nothing about it can be widened into access to the project.

03What unlocks what

The five stages are not tabs. Each one is gated on a decision the admin has to take deliberately, and two of those gates are expensive to reverse.

04The decisions inside stage 3

Stage 3 carries the method's only arithmetic, and three decisions that change the answer. Each respondent scores every initiative on three criteria at one to five — Low 1 · Moderate 3 · High 5 — so one person contributes at most fifteen points to an initiative.

05What the system refuses

A map is as much about the roads that are not there. These are enforced on the server, not by hiding a button:

AttemptResult
Another tenant's project Not found — identical to a project id that was never real
A contributor reaching the project No route exists; the token resolves to one task and stops
Scoring an item off your own list version Rejected — the item must belong to the version you were invited to
Submitting a partial response Blocked, with the count of what is still blank
Editing the list after invitations Locked; a change means a new version, never a silent edit
Deleting without typing the name Rejected server-side, not merely a disabled button
Reminding the same person repeatedly Rate-limited to once a day, and every send is logged
OZ staff reading client strategy No path built — the back office holds metadata only
